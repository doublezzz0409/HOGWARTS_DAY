# HOGWARTS_DAY

### 一套研究驱动、面向第一人称世界体验视频创作的 Agent 工作流

**English** · [中文](#) · [Read the English version →](README.md)

**让观众不只是观看一个世界，而是想要生活在其中。**

HOGWARTS_DAY 是一个面向 AIGC 视频创作的创意工作流项目。它的目标不是单纯生成视频，而是建立一条可复用的创作管线：从 **世界研究 → 整集创意策划 → 场景与镜头导演设计 → AI 视频生成提示词加工**。

虽然 HOGWARTS_DAY 是当前的实践项目（魔法世界题材），但它被设计为**跨题材、跨项目可复用**——不是一个只为制作霍格沃茨视频而写的提示词仓库。

> 如实说明：跨项目架构已有基础，但**尚未通过不同题材的完整实战验证**。v0.1 工作流仍在积极开发中，究竟哪些已验证、哪些未验证，见[当前开发状态](#-当前开发状态)。

## ✨ 愿景

是什么让观众爱上一个虚构世界？

不只是壮丽的风景、奇异的生物，或强大的魔力——而是一种感觉：那个世界里，正有一种生活等着他们去经历。

一个可以去的地方。一段可以去体验的日常。一个值得记住的小小发现。一个可以一起消磨时光的人。一个让人不愿离开的世界。

项目围绕一个核心创意追求而构建：

> **让观众想要住进他们刚刚看过的那个世界。**

贯穿全部创作的四阶段观众旅程：

**认识 → 体验 → 连接 → 渴望**

| 阶段 | 创意目标 |
|---|---|
| 认识 | 呈现一个独特、值得探索的世界。 |
| 体验 | 让观众想象自己参与到它日常的活动与非凡的时刻之中。 |
| 连接 | 通过日常、关系与细节建立情感依恋。 |
| 渴望 | 让观众希望自己能留下、去体验更多。 |

创作管线从**世界研究**走向**观众体验设计**，再走向**视频生成**：先理解世界，再决定要让观众体验什么，最后产出能在屏幕上实现它的提示词。

## 🧭 工作流总览

项目把创作工作组织为若干长期工作流。当前已定义的有三个：

| 工作流 | 职责 | 定义状态 |
|---|---|---|
| **WF-01 · 世界研究** | 研究创作对象的世界、设定、地点、生活方式、体验，以及可用于视频创作的素材。产出世界知识与候选体验。 | 已有实战研究；正式规范尚未汇总入仓（见状态） |
| **WF-02 · 整集创意策划** | 从创意种子出发，经七阶段流程形成完整的整集导演稿。 | 已完成首次实战闭环（V0.2.1），正式关闭 |
| **WF-03 · 导演稿 → 视频生成提示词加工** | 按导演指定的范围与策略，把 WF-02 导演稿加工为可执行的视频生成提示词。 | 定义 v1.1 已批准；已完成首次实战加工；长期稳定性未验证 |

> WF-04（全局导演整合）与 WF-05（制作与复盘）在 `WORKFLOW_SPEC.md` 中有概要规格，但**尚未启动**。

详细定义见 **`WORKFLOW_SPEC.md`**（WF-00~WF-05）与 **`core/WF-03-导演稿到视频提示词加工工作流-v1.0.md`**（WF-03 权威规格）。README 只做概览，规格文件才是权威。

### WF-01 · 世界研究

研究创作对象的世界：原著、设定、地点、生活方式、体验与可用素材。核心目标是为下游创作**提供世界知识与候选体验**。

产出：带来源与可信度标注的世界研究文档，以及**候选体验清单**（候选体验会被标注，未获导演认可前不当作已认可资产）。

> 说明：WF-01 已完成一次正式实战研究，但**该研究报告未包含在本次工作流提交中**，仍待事实校正与导演验收。项目尚未把汇整后的正式 WF-01 规范写入仓库。

### WF-02 · 整集创意策划

从创意种子出发，形成完整的整集导演稿。其七阶段流程：

1. **创意接收与任务定义**
2. **创意开发与体验筛选**
3. **整集体验组合与结构设计**
4. **观众注意力与体验兑现审查**
5. **SC 场景规划**
6. **SH 镜头级导演设计**
7. **整集整合、质量检查与交付**

**Agent 架构：**

- **一个主 Agent** 负责整体策划、调度、整合和最终交付。
- 专业角色按需参与：**M1** 创意生成，**M2** 体验评估，**M3** 结构设计，**M4** 注意力设计。
- 专业 Agent **按需调用，不是强制并行流水线**。
- **导演保留关键创意决策与审批权。**

**SC 与 SH：**

- **SC（场景单元）**——整集的一个场景单元。
- **SH（镜头设计单元）**——镜头级设计单元。
- **SH 不等于视频生成片段。** 一个 SH 可以拆分成多个生成任务。

### WF-03 · 导演稿 → 视频生成提示词加工

把 WF-02 导演稿加工为可执行提示词。关键特性：

- **以 SC 为基本加工单位**，但导演可以指定完整 SC、单个 SH、多个 SH，或具体生成任务。
- **由一个主 Agent 独立完成**指定加工任务。
- 每次任务都实际读取 **WF-02 正式导演稿**、**ACTING Skill** 与 **CINEDANCE Skill**。
- **ACTING** 负责适用情况下的角色可观察表演（仅限画面内角色；纯 POV 无人在画时不编造表演）。
- **CINEDANCE** 负责空间、首帧、光学、摄影机、物理、光线、连续性、提示词装配与 QA。
- 支持**纯文字 T2V、参考图、首尾帧、多参考、混合**等策略，由导演指定。
- 交付**完整可执行提示词、生成任务映射、参考素材清单与质量检查结果**。

WF-03 **不重新设计导演意图**，也不擅自改变导演指定的生成策略。

## 🤖 Agent 架构与 DSH

项目以 **DSH（DeepSeek Harness）** 作为当前的执行环境。工作流围绕**主 Agent** 设计：主 Agent 负责路由与整合，专业子 Agent 与 Skill 按需调用——不是固定的并行流水线。

**仓库内附带两份可复用 Skill**（位于 `.dsh/skills/`），是 WF-03 的执行依赖：

| Skill | 作用 |
|---|---|
| `acting` | 视频提示词的角色表演层：目标、节拍、策略、潜台词、身体/地位、眼神、声音。 |
| `cinedance-higgsfield` | 面向 Seedance 2.0 / Higgsfield 的电影化提示词导演：场景上下文、空间调度、首帧、光学/视野、摄影机、时间、物理、光线、声音、连续性、参考控制与最终提示词装配。 |

> `.gitignore` 采用**精确例外**：只跟踪这两份指定 Skill，不跟踪整个 `.dsh/` 本地运行环境。其余 `.dsh/` 内容仍留在本地、不入库。

工作流资产**并不绑定 DSH**——规则以可移植文档的形式编写。迁移或适配到其他 Agent 环境在原则上可行，但**尚未验证**。

## 📂 项目组织

仓库把**通用工作流资产**与**具体项目实例**分开管理。

### 通用工作流资产

- **`core/`**——可复用的工作流定义（如 WF-03 规格）。
- **`planning/WF-02/`**——可复用的 WF-02 研究方法与知识资产（M1–M4）。
- **`.dsh/skills/`**——两份可复用 Skill（`acting`、`cinedance-higgsfield`）。
- **根目录规则与入口文档**——`AGENTS.md`、`PROJECT_RULES.md`、`WORKFLOW_SPEC.md`、`DECISION_LOG.md`、`PROJECT_STATE.md`。

### 具体项目实例

- **`planning/EPxx/`**——某一集的创意简报、导演稿、场景规划等。
- **`production/EPxx/`**——某一集的生成提示词、参考素材与视频产物。

某一集的创意、导演稿、生成提示词、参考素材与视频产物，与通用工作流资产**分开管理**。可复用方法放在 `core/` 与 `planning/WF-02/`；某一集的具体材料放在 `planning/EPxx/` 与 `production/EPxx/`。

> 说明：某一集的材料并非一定全部纳入 Git。通用工作流资产与具体项目实例按不同边界管理，大体积制作产物（视频、渲染中间物、图片素材）由 `.gitignore` 排除。

## 🚀 快速开始

1. **获取仓库。**
   ```bash
   git clone https://github.com/doublezzz0409/HOGWARTS_DAY.git
   cd HOGWARTS_DAY
   ```
2. **确认 DSH 环境。** 工作流假定以 DSH 作为当前执行载体。
3. **确认项目规则已加载。** `AGENTS.md` 是入口，引用 `PROJECT_RULES.md`（规则全文）与 `DECISION_LOG.md`（导演决策）。
4. **确认两份 Skill 能按名发现**：`.dsh/skills/acting/` 与 `.dsh/skills/cinedance-higgsfield/`。
5. **准备独立的项目目录与项目上下文**（如为新一集准备 `planning/EPxx/`、`production/EPxx/`）。
6. **按实际需求调用相应工作流：**
   - 世界/设定/生活体验问题 → **WF-01**
   - "这一集讲什么" → **WF-02**
   - "把导演稿变成视频生成提示词" → **WF-03**

> 这是一个仍在开发中的创意工作流，不是打包软件。**没有一键安装或自动化脚本**；部分步骤（DSH 环境、Skill 注册、项目上下文）需要**人工部署**。

## ⚠️ 限制与路线

**尚未验证的能力：**

- **没有真实观众数据。** 留存、心理、"观众是否真的想生活在这个世界"都没有被测量。注意力类发现基于第三方结构分析，而非平台后台指标。
- **跨项目复用未经证明。** 架构设计上可泛化到霍格沃茨之外，但尚未在不同题材上用完整真实制作验证。
- **WF-03 的长期稳定性未验证。** 一次真实加工（EP01 SC03）不等于持续可靠已获证明。
- **参考素材基本缺失。** 角色/地点/道具参考图与角色档案/声音库尚不存在，因此基于参考图（R2V）的身份一致性暂无法真正执行。
- **事实状态尚未完全落定。** 部分 WF-01 原著事实与一处连续性项仍待核验；下游提示词须保留这些标注，不得当作已确认。
- **M5/M6 暂缓**，因此制作可行性、连续性/成本风险、整集质量目前依赖导演人工把关。
- **不绑定单一 Agent 框架。** 除 DSH 外的可移植性是既定目标，不是已测试的事实。

**走向验证：** 预期的下一步是从研究转向**以创作驱动的实际验证**——用 M2/M3/M4 规划一支最小样片，再从真实生成与复盘中学习。这验证的是设计逻辑，**不能替代观众数据**。

## 📜 项目原则

1. **体验重于奇观。** 视觉奇观服务于有意义的观众体验。
2. **生活重于说教。** 让观众通过亲身经历，去理解一个世界如何运转。
3. **情感重于信息。** 事实让世界可被理解，情感连接让世界被记住。
4. **研究先于虚构。** 尊重原始资料，清晰标识创意诠释。
5. **批准先于推进。** 明确的决策边界；导演掌握最终创意决定权。
6. **可复用知识重于一次性产出。** 把已批准的发现沉淀为可复用的工作流资产。

规则全文见 [`PROJECT_RULES.md`](PROJECT_RULES.md)；六个工作流的输入/任务/输出见 [`WORKFLOW_SPEC.md`](WORKFLOW_SPEC.md)；导演决策见 [`DECISION_LOG.md`](DECISION_LOG.md)；实时项目状态见 [`PROJECT_STATE.md`](PROJECT_STATE.md)。

## 🌍 超越霍格沃茨

HOGWARTS_DAY 以魔法世界作为最初的创作环境，但更大的愿景是一套**可跨不同虚构世界复用的第一人称世界体验视频创作方法**。

一所魔法学校。一座未来城市。一个奇幻王国。一个只存在于想象中的世界。

背后的问题始终如一：

**如果观众能进入这个世界度过一天，是什么会让他们希望永远留下来？**
