# HOGWARTS_DAY

### 可复用的第一人称世界体验叙事工作流

**English** · [中文](#) · [Read the English version →](README.md)

**让观众不只是观看一个世界，而是想要生活在其中。**

HOGWARTS_DAY 是一套可复用的创意工作流，用于设计第一人称世界体验故事与沉浸式短视频。

它探索如何把一个虚构世界中的地点、活动、日常与情感体验，转化为引人入胜的视听作品，让观众产生"若能走进那个世界该多好"的向往。

---

## ✨ 愿景

是什么让观众爱上一个虚构世界？

不只是壮丽的风景、奇异的生物，或强大的魔力。

而是一种感觉：那个世界里，正有一种生活等着他们去经历。

一个可以去的地方。
一段可以去体验的日常。
一个值得记住的小小发现。
一个可以一起消磨时光的人。
一个让人不愿离开的世界。

HOGWARTS_DAY 围绕一个核心创意追求而构建：

> **让观众想要住进他们刚刚看过的那个世界。**

目标不是简单呈现一堆漂亮的镜头，而是设计出让观众能够把自己想象成参与者、而非远处旁观者的体验。

## 🎯 核心体验设计

本项目探索一段四阶段的观众旅程：

**认识 → 体验 → 连接 → 渴望**

| 阶段 | 创意目标 |
|---|---|
| 认识 | 呈现一个独特、值得探索的世界。 |
| 体验 | 让观众想象自己参与到它日常的活动与非凡的时刻之中。 |
| 连接 | 通过日常、关系与细节建立情感依恋。 |
| 渴望 | 让观众希望自己能留下、去体验更多。 |

三个创意维度支撑这段旅程：

- **世界奇观：** 什么让观众停下脚步、驻足凝视？
- **独特体验：** 什么让观众想要亲身参与？
- **生活与情感：** 什么让观众想要留下？

## 🧭 工作流

HOGWARTS_DAY 采用分阶段创意工作流。每个阶段都有明确的职责与交付物。

| 工作流 | 职责 |
|---|---|
| WF-00 · 项目初始化与任务分流 | 确立项目背景、约束与任务归属。 |
| WF-01 · 世界生活研究 | 考察世界的原著事实、日常生活、活动、地点与体验机会。 |
| WF-02 · 创意策划 | 制定整体创意方向与体验策略。 |
| WF-03 · 场景开发 | 通过迭代式创意评审与批准来设计单个场景。 |
| WF-04 · 导演整合 | 将已批准的场景连接为连贯的视听体验。 |
| WF-05 · 制作与复盘 | 准备制作、评估结果，并将洞见反馈回工作流。 |

### WF-01 与 WF-02 的边界

研究与策划之间的职责划分是刻意的、清晰的：

- **WF-01** 负责弄清楚：这个世界里有什么值得体验。
- **WF-02** 负责决定：我们要带观众体验什么，以及如何把这些体验组织成一个有吸引力的整体。

简言之：WF-01 找出有哪些体验可做，WF-02 选定要体验什么、并决定如何组织。

### WF-02 多维创意决策地图

> 这是后续研究的覆盖清单，不是已经确定的评分表。

**01. 观众吸引力**

- 是否能激发好奇？
- 是否具有广泛的兴趣基础？
- 是否有独特、清晰的观看承诺？
- 是否能让不同背景的观众理解？

**02. 体验价值**

- 观众究竟能体验到什么？
- 是观看、参与、探索，还是获得某种身份？
- 有没有现实世界无法提供的体验？
- 是否产生「我也想亲自经历」的欲望？

**03. 世界独特性**

- 是否充分体现这个世界的独有规则？
- 是否只是普通生活换了一套魔法皮肤？
- 是否展示了世界不为人知的一面？
- 是否符合原著和世界观依据？

**04. 情绪与心理连接**

- 是否产生惊叹、快乐、温暖、好奇或放松？
- 是否产生归属感？
- 是否让观众向往这里的生活？
- 是否形成情绪上的记忆点？

**05. 体验之间的关系**

- 几个体验能否相互连接？
- 是否有先后顺序和因果关系？
- 是否重复表达同一种价值？
- 组合后是否产生单独体验不具备的新价值？

**06. 整体叙事与节奏**

- 一天是否有完整的体验弧线？
- 是否有开场、发展、高潮和结束？
- 是否存在无聊、拥挤或断裂的部分？
- 是否有足够的变化和期待？

**07. 注意力与传播**

- 如何吸引点击？
- 如何持续提供观看理由？
- 如何设置信息释放和惊喜？
- 如何兑现开头的承诺？
- 是否具有分享和讨论价值？

**08. 制作与实现**

- AI 是否能可靠实现？
- 人物、空间、魔法是否容易漂移？
- 是否需要参考图或复杂连续镜头？
- 制作成本与收益是否合理？
- 是否存在版权、事实或安全问题？

**09. 系列化与长期价值**

- 是否能形成系列特色？
- 是否有其他世界或地点可以延伸？
- 是否容易让观众期待下一集？
- 是否帮助建立独特的频道品牌？

### WF-02 整体研究路线

1. **模块 0：研究基础与问题地图** · 前期方案已建立
   明确研究目标、问题范围、研究对象、证据要求和模块之间的边界。

2. **模块 1：创意生成机制** · 已形成阶段性研究成果
   研究如何产生创意、发现机会、进行创意变形、跨领域迁移和深化。

   核心问题：我们如何找到值得拍摄的创意？

3. **模块 2：体验价值与筛选机制** · 当前阶段，待能力检验
   研究如何识别体验价值、判断体验是否值得拍摄、区分不同价值及其证据。

   核心问题：一个体验为什么值得拍摄？

4. **模块 3：体验组合结构** · 尚未启动
   研究如何将多个体验组织在一起，形成有层次、有变化、有整体吸引力的一集。

   核心问题：多个好体验如何组合成一集好视频？

5. **模块 4：观众注意力与体验兑现** · 尚未启动
   研究开头吸引、注意力维持、观看过程、期待建立、体验兑现和观众满足。

   核心问题：如何让观众愿意看下去，并获得承诺的体验？

6. **模块 5：制作约束与质量验证** · 尚未启动
   研究创意的制作可行性、AIGC 实现约束、质量风险与验证方式。

   核心问题：一个好创意如何真正被高质量地制作出来？

7. **模块 6：整合、案例验证与方法迁移** · 尚未启动
   整合前面研究成果，进行综合案例验证，提炼可迁移的方法。

   核心问题：如何让前面所有研究形成一套真正能工作的创意策划体系？

### WF-02 后续模块开发纪律

**适用范围：模块二剩余开发，以及模块三、模块四、模块五、模块六的全部研究与开发工作。**

#### 一、始终围绕路线图，不允许研究方向漂移

WF-02 的目标是把 WF-01 提供的世界体验候选，加工成真正值得观众观看的视频体验设计。每个模块必须围绕路线图中已经确定的核心任务推进：

- **模块二：体验价值与筛选机制**——解决什么样的体验值得进入视频，为什么值得，如何判断和筛选。
- **模块三：体验组合与整体结构**——解决多个体验如何组合，怎样形成有吸引力的整体，而不是简单堆砌精彩片段。
- **模块四：观众注意力与体验兑现**——解决观众为什么点击、为什么继续看、期待如何建立和兑现，以及观看过程中如何获得满足。
- **模块五：制作约束与质量验证**——解决有价值的创意如何在实际制作中实现，以及如何判断最终成片质量。
- **模块六：整合、案例验证与方法迁移**——解决各模块能否形成完整决策体系，能否通过真实案例验证，并沉淀为可复用的方法。

不能因为研究过程中出现了某个有趣的理论问题，就把它升级为新的主线。

#### 二、先研究真实内容，再总结方法

1. 优先研究真实创作者、真实作品、真实场景和真实观众体验。
2. 研究必须深入到具体内容：创意是什么、开头怎么呈现、过程如何推进、观众期待如何变化、惊喜和满足在哪里发生。
3. 不允许只罗列抽象概念、机制名称和理论分类，就声称完成了研究。
4. 不能用框架代替案例，也不能用案例数量代替研究深度。
5. 尤其要持续围绕野兽先生的真实作品学习，研究其内容为什么值得观看，再思考如何迁移到霍格沃茨世界。

#### 三、禁止为了框架完美而无限打磨

1. 不追求理论上的绝对完整，不追求概念边界毫无争议。
2. 不因非关键措辞、分类方式、术语命名等问题反复修改已经能够工作的框架。
3. 只有当问题会实质性影响研究结论、判断准确性、模块职责或后续执行时，才值得停下来处理。
4. 能通过现有材料、证据和合理推理解决的问题，尽量在当前阶段一次解决，不要习惯性推迟到下一阶段。
5. 已经达到当前任务目标的成果，应当及时收敛，不要为了寻找新问题而继续审查。

**研究框架是工具，不是研究成果本身。**

#### 四、问题处理必须区分轻重缓急

发现问题时，先判断它属于哪一类：

- **阻断性问题：** 会导致核心结论错误、任务无法执行或模块职责混乱。必须解决后再继续。
- **实质性问题：** 会影响结论质量，但可以在当前研究中补充证据或修正。原则上当前解决。
- **一般性问题：** 不影响当前目标，可以记录，不应阻断开发。
- **优化性问题：** 只是让表达、分类或框架更漂亮。没有明显收益时不做。

不能把所有发现的问题都当成必须返工的问题。

#### 五、保持研究严谨，但不制造虚假的严谨

1. 区分事实、原始证据、创作者表达、研究分析、推断和待验证假设。
2. 不把推断包装成事实，不把没有观众数据支持的判断包装成实际观众反馈。
3. 证据不足时，明确说明不确定性，不必为了追求完整而无限寻找证据。
4. 不因缺少某一种理想证据，就否定其他已有证据的研究价值。
5. 不把单一案例的发现直接推广成普遍规律。
6. 结论要与证据强度相匹配。

#### 六、每个模块都必须产生实际开发成果

每个模块不能只留下研究方案、问题清单、概念框架和待办事项。必须逐步形成：

- 对该模块核心问题的实际回答；
- 有真实案例支撑的研究发现；
- 可以用于具体创意决策的方法；
- 必要的判断依据、反例和适用边界；
- 可以交给下游模块使用的明确输出。

尤其要避免模块之间相互等待：不能因为下游模块还没开发，就拒绝在当前模块形成可用成果。

#### 七、模块之间要有清晰分工，但不能人为制造壁垒

1. 只处理当前模块真正负责的问题。
2. 遇到跨模块问题时，先解决当前模块能够解决的部分。
3. 只有确实需要下游模块深入处理的内容，才交接。
4. 不要把本来能够在当前阶段解决的问题，习惯性标记为"留给模块三""留给模块四"。
5. 下游模块应当使用上游成果，而不是反复推翻上游已经完成的研究。

#### 八、开发过程要有明确的收敛意识

每个研究阶段都要回答三个问题：

1. 当前模块最初要解决的问题是什么？
2. 现在已经解决了什么，还有哪些实质性问题没有解决？
3. 剩余问题是否真的阻止模块完成？

如果核心目标已经达到，剩余问题只是一般性优化，就应当结束当前阶段，进入下一项工作。不要为了让报告看起来更完整，不断增加研究任务。

#### 九、我的工作责任

作为研究与开发协作伙伴，必须：

- 主动推动真实研究，而不是被动地不断设计流程。
- 主动指出研究中的错误，但不能把挑错变成主要工作。
- 对问题的严重程度作出判断，而不是发现问题就要求返工。
- 优先交付有实际用途的成果。
- 不擅自改变路线图，不擅自扩大研究范围。
- 不把尚未验证的框架说成成熟体系。
- 不为了显得专业而制造复杂度。
- 当导演指出偏离中心时，立即回到模块的核心任务，不为之前的复杂工作辩护。

#### 十、最终原则

**我们开发 WF-02，是为了学会如何创作真正吸引观众的视频，而不是为了开发一套看起来完美的理论体系。**

研究要深入，判断要严谨，框架要够用，成果要能落地。宁可完成一个有真实案例、有明确结论、能够实际使用的模块，也不要花大量时间打磨一个始终无法进入实际创作的完美框架。

**以解决问题为终点，以实际可用为验收标准，以整体路线图为方向。**

### 受控的创意流程

工作流强调明确的决策与阶段边界：

- 先研究，再策划。
- 先观众体验，再镜头设计。
- 逐个开发、评审、修改、批准各场景。
- 保持"已核实资料"与"创意诠释"之间的界线。
- 不把建议当作已批准的决策。
- 未满足所需条件，不得推进阶段。

最终创意决定权归导演。AI 代理在明确划定的边界内，协助研究、分析、策划、文档与制作任务。

## 🏗️ 架构

项目把可复用的工作流规则与世界专属知识分离。

```text
HOGWARTS_DAY/
│
├── core/           # 可复用的工作流基础
├── world/          # 世界专属知识
│   ├── canon/      # 原著事实与原始资料
│   ├── experience/ # 世界体验与研究结果
│   └── references/ # 辅助参考资料
│
├── planning/       # 创意策划
├── scenes/         # 单个场景开发
├── director/       # 导演层面的整合
├── production/     # 制作素材
├── reviews/        # 评审与复盘
├── assets/         # 已批准的、可复用的创意素材
│
├── AGENTS.md
├── PROJECT_RULES.md
├── PROJECT_STATE.md
├── WORKFLOW_SPEC.md
└── DECISION_LOG.md
```

架构设计旨在让两类知识保持区分：

**可复用的工作流知识**

方法、流程、决策规则、评审标准与协作协议——可跨不同虚构世界复用。

**世界专属知识**

属于某一特定世界的原著事实、地点、角色、活动、参考资料与已批准的体验设计。

这种分离意在让工作流可以超越霍格沃茨、适用于更广的世界。

## 🤖 人类主导，AI 协作

本项目把 AI 视为协作式生产系统，而非自主的创意权威。

协作模型建立在若干原则之上：

- 由人类导演定义创意意图并做出最终决策。
- AI 代理在明确范围内执行被委派的任务。
- 研究结论必须保留可追溯的来源。
- 创意提案必须与已确认的决策保持可区分。
- 已批准的体验与可复用的发现可作为项目素材被保存。
- 文件修改与 Git 操作需要明确授权。

项目同时维护决策记录与项目状态文档，以降低长期创意会话中的歧义。

## 🚀 项目原则

1. **体验重于奇观。** 视觉奇观固然重要，但它应服务于有意义的观众体验。
2. **生活重于说教。** 让观众通过亲身经历，去理解一个世界如何运转。
3. **情感重于信息。** 事实让世界可被理解，情感连接让世界被记住。
4. **研究先于虚构。** 尊重原始资料，并清晰标识创意诠释。
5. **批准先于推进。** 在整个开发过程中保持明确的决策边界。
6. **可复用知识重于一次性产出。** 把已批准的发现沉淀为可支撑未来创作的素材。

## 🌍 超越霍格沃茨

HOGWARTS_DAY 以魔法世界作为最初的创作环境。

然而，更大的愿景是：为不同虚构世界创作第一人称体验，发展出一套可复用的方法。

一所魔法学校。
一座未来城市。
一个奇幻王国。
一个只存在于某人想象中的世界。

背后的问题始终如一：

**如果观众能进入这个世界度过一天，是什么会让他们希望永远留下来？**

## 英文摘要

HOGWARTS_DAY 是一套实验性的、可复用的第一人称世界体验叙事工作流。

它把世界研究、观众体验设计、场景开发、导演层面整合与制作复盘，组合成一个结构化的"人机协作"流程。

它的核心追求，是让人们不再只是看到一个虚构世界长什么样，而是去感受生活在那里会是怎样的体验。

**项目始于霍格沃茨，但工作流的设计远不止于此。**
