## 0. 模块三是什么

- **核心问题**：**当我们拥有多个值得呈现的体验时，怎样把它们组织起来，形成一个有整体吸引力、有发展、有变化、有完整体验回报的视频？**
- **目标**：产出**整体内容构想 + 组织关系 + 发展设计 + 连贯性判断**——回答"这些体验为什么该在同一视频里、怎么排、怎么发展、结尾怎么收"。
- **输入**：
  1. 一组**候选体验/内容单元**（来自 WF-01 候选体验、模块一创意、或导演方向）；
  2. **各单元的价值判断**（来自模块二：JB 价值结论 / JC 兑现边界 / 价值类型）；
  3. **整集目标/观看承诺**（来自导演或上游；模块三**不自行发明**整集目标，缺输入时标"条件不足"）。
- **输出**：整体内容构想卡、单元登记表、关系图谱、节拍脊柱表、组合层价值声明、方案必要性删除测试、缺陷诊断、多方案比较——**供导演取舍、供模块四/五使用**。
- **不做什么（边界）**：
  - **不重判**单个体验价值（模块二）；
  - **不设计**点击/钩子/留存/信息释放节奏/结尾留存（模块四）；
  - **不做**技术可行性、预算、排期、模型测试（模块五）；
  - **不整合**跨模块成完整决策体系（模块六）；
  - **不替导演**定稿——只出候选方案，最终选择权属导演。

> **一句话定位**：模块二回答"哪个体验值得进入视频"；**模块三回答"这些值得的体验怎么组成一个好视频"**。

## 1. 五个必须坚持的区分（模块三的地基）

1. **"单项价值高" ≠ "适合放进这个整体"**：一个体验再不替代，若在整体里没有功能、与其它单元重复或冲突，也不该硬塞（呼应模块二 C3"高价值≠必保留"）。
2. **"并列"不等于"组合"**：把多个好场景依次播放 = 清单，不是作品。组合必须产生**单元各自没有的整体价值**。
3. **"变化"不等于"堆叠"**：换地点/换道具/换噱头而**体验组织方式不变**，是**伪发展**，不是真发展。
4. **"组合层价值" 与 "单项价值" 分开记**：整体价值（对比/累积/因果闭合/呼应/情绪弧/身份获得）**不能**由任一单项价值之和推出，也不可反过来给单项加分。
5. **"结构" ≠ "留存优化" ≠ "可行性"**：结构好不好（是否连贯/有发展/有整体回报）是模块三的事；观众是否看到第几分钟（模块四）、做不做得出来（模块五）分别另判，**不得拿"这样做更抓人"替代"这样组织更成立"**。

## 3. 七步操作流程（面对"一组候选体验 → 一个整体作品构想"）

> 顺序是**建议**，不是强制线性；可回溯、可迭代。**不要求七个环节=七个 Agent 或七个审批节点。**

### 第 1 步 · 定"整体承诺"（Organizing Promise）
- **做什么**：用**一句话**说清"这个视频是什么 + 观众将被带去获得什么"。它来自导演/上游目标；若没有，则**提出候选承诺并标 `[待导演确认]`**，不得自行当定稿。
- **判据**：这句话能否解释"为什么是这些体验、为什么不是别的"？说不出 → 承诺还不成立，别急着排单元。
- **产出**：整体承诺一句话 + 观看身份（我是谁：新生/访客/某个居民）+ 期望的情绪落点。

### 第 2 步 · 候选"单元化"（Unit Register）
- **做什么**：把每个候选体验转成一个**内容单元**并登记（不重判价值，只标注与组织有关的属性）：
  - 单元名 / 来源（WF-01 候选编号 / 模块一 / 其它）；
  - **价值类型**（承接模块二：竞争型/生活型/奇观型/关系型/混合）；
  - **观众"具体做什么"**（一个可想象的动作：接信/挠梨子/报口令/走三趟）；
  - **自然入口/出口**（怎么进、怎么离开这个单元）；
  - **时长权重**（轻/中/重）；
  - **它自带的钩子**（为什么有意思，只作组织参考，不作留存判断）；
  - **价值判断状态**（模块二已判 / 待判——**待判的不得当"已高价值"使用**）。
- **产出**：**单元登记表**。

### 第 3 步 · 关系图谱（Relationship Map）
- **做什么**：对"候选单元两两之间"判断关系类型（见 §5）。目标不是"选最好的"，而是找出**能产生整体增值的关系**，并识别重复/冲突。
- **必答**：这些体验之间，是**因果 / 依赖 / 递进 / 对比 / 呼应 / 过渡 / 并列 / 重复 / 冲突**中的哪几种？至少要有一种"增值关系"。
- **产出**：**关系图谱**（可用"单元×单元"矩阵，每格填关系类型与理由）。

### 第 4 步 · 选"脊柱" + 分配"结构角色"（Spine & Roles）
- **选脊柱**：从六种组织逻辑中选一个（可组合，但需主脊柱明确）：
  - A 单一事件时间轴 / B 淘汰阶梯 / C 阶梯对比 / D 主题合辑 / E 建造交付 / **F 旅程·探索·时间流**（HOGWARTS 主用，见 §5）。
  - **HOGWARTS 首选不是 B/C**（竞争/价格阶梯不适配目标），而是 **F（时间流/旅程/线索）** 或 **D（主题合辑）** 的温和变体。
- **分配角色**：把单元按 **开头 / 发展 / 转折 / 高潮 / 结尾** 分工（原则见 §5.2）：
  - **开头**：承诺清晰 + 高好奇 + 当场兑现一点 + **埋线**；
  - **发展**：价值类型轮换、逐步加深、制造新期待；
  - **转折**：一个"变奏"（意外/反差/新信息），防中段塌；
  - **高潮**：前面铺垫所指向的**情绪/体验顶点**（不必是最大奇观）；
  - **结尾**：回收埋设 + 情绪落点 + 留白。
- **产出**：脊柱声明 + 角色分配表。

### 第 5 步 · 设计"发展"（Development Design）
- **发展轴**：明确"**什么在增长/加深**"（好奇心？亲密感？规模？危险？归属？认知？）。**一条主轴**为主，可辅以一条副轴。
- **承诺-兑现链**：开头承诺 → 中段逐步兑现一部分 → 高潮大兑现 → 结尾余韵。
- **埋设-回收（setup-payoff）**：至少一条贯穿全片的线（一个物件/一句话/一个目标/一个邀请），早埋晚收。
- **前向桥接**：单元之间用"**指向下一段**"过渡（"但这还不如接下来…"），不用"上一段结束了"的后向总结。
- **张弛节奏**：快/慢、密/疏、公共/私密、宏大/细微交替；避免连续同强度。
- **产出**：**节拍脊柱表**（每段：观众做什么 / 新信息或新期待 / 与前后如何连接 / 结构角色 / 时长权重）。

### 第 6 步 · 组合层价值 + 方案必要性（Emergent Value & Necessity）
- **组合层价值**：显式写出"**整体才有、任一单元单独没有**"的价值（见 §6 清单，至少命中 2–3 类）。
- **方案必要性删除测试**（§8）：对每个单元做"删除它，当前**方案**失去什么"的三层判断（结构/铺垫回收/反差节奏）。三层皆无 → 该单元在**本方案**中非必要（可删/可并/可换），**但这不否定其单项价值**。
- **产出**：组合层价值声明 + 删除测试表。

### 第 7 步 · 缺陷诊断 + 多方案比较 + 移交（Diagnose & Compare & Hand-off）
- **缺陷诊断**：逐项过 §7 的 8 类缺陷，标注命中项与修复方向。
- **多方案**：产出 **2–3 个可行方案**（同一批单元、不同脊柱/角色/顺序），比较其"整体承诺匹配 / 发展自然度 / 组合增值 / 缺陷风险 / 交付边界"。
- **移交**：钩子/留存/信息释放 → 模块四；技术/预算/连续性 → 模块五；**均标 `[待导演确认]`**。
- **产出**：缺陷诊断表 + 方案比较表 + 推荐候选方案（**候选，非决策**）。

## 5. 关系类型、组织逻辑与结构角色（速用）

### 5.1 六种组织逻辑（脊柱）
> 详见《野兽先生作品结构研究》§3；此处为选用速查。

| 逻辑 | 脊柱 | 适配 HOGWARTS？ |
|---|---|---|
| A 单一事件时间轴 | 连续时间/单一事件 | 部分（"一整天"可视为长事件） |
| B 淘汰阶梯 | 人数递减轮次 | **差**（竞争内核与目标冲突） |
| C 阶梯对比 | 价格/规模递增 | **差**（无价格阶梯；可借"体验强度递增"的表层） |
| D 主题合辑 | 一个母题 + 累积 | **好**（如"第一次""被善待的瞬间"合辑） |
| E 建造交付 | 建造→使用→交付 | 中（如"布置宿舍/准备一场聚会"） |
| **F 旅程/探索/时间流** | 空间路线/时间流逝/线索 | **最好**（"一天""一封信引路""城堡深处"） |

### 5.2 结构角色原则
- **开头**：承诺清晰 + 违反日常直觉的好奇点 + 当场兑现一点 + 埋一条贯穿线。
- **发展段**：轮换价值类型（别连续同一种），逐步加深发展轴，制造"接下来会怎样"。
- **转折**：中段至少一次"变奏"（新信息/反差/意外），防止"一节一节往下走"的疲劳。
- **高潮**：应是**前面铺垫指向的情绪顶点**；把最大奇观当高潮是常见错（易纯奇观）。
- **结尾**：回收埋设 + 情绪落点（归属/温暖/满足）+ 留白（世界还在，我还没走完）。

### 5.3 九种单元关系（用于关系图谱）
| 关系 | 判定问句 | 好/坏 |
|---|---|---|
| **因果** | A 是否导致/引发 B？ | 好——最强粘合 |
| **依赖** | B 是否必须先有 A（口令/许可/线索）？ | 好——天然顺序 |
| **递进** | B 是否比 A 更强/更深/更近？ | 好——提供发展 |
| **对比** | A 与 B 是否形成反差（冷/暖、公共/私密）？ | 好——但须可调和 |
| **呼应** | A 埋的东西 B 是否回收？ | 好——闭合感 |
| **过渡** | A 是否只是把观众送向 B？ | 中性——低权重，但可防割裂 |
| **并列** | A、B 是否只是"又一个"？ | 差——除非有母题/计数/人物线粘合 |
| **重复** | A、B 是否提供同一种价值/情绪/机制？ | 差——边际递减 |
| **冲突** | A、B 是否互相削弱（基调/逻辑打架）？ | 差——须调整或删 |

## 6. 组合层价值清单（整体才有、单元单独没有）

> 组合层价值 = **靠"放在一起"才产生的价值**。一个方案至少命中 2–3 类，否则多半是拼盘。

1. **对比反差**：冷/暖、公共/私密、快/慢、宏大/细微互相增强。
2. **递进累积**：强度/亲密度/规模层层加深，结尾更有分量。
3. **因果闭合**：前因后果、目标达成，产生"完整感"。
4. **呼应回收**：早埋晚收，产生"啊原来"的记忆点。
5. **情绪弧线**：好奇→紧张→惊喜→温暖→归属的完整情绪旅程。
6. **身份获得**：（HOGWARTS 特有）"我做过这些"→"我是这里的一员"。
7. **整体记忆点/余韵**：一句话能概括的整体印象 + 留下想再来的愿望。
8. **世界观拼合**：多个侧面共同拼出一个"活着的、可生活的世界"。

## 7. 连贯性与缺陷诊断（八类，速查）

| # | 缺陷 | 识别问句 | 修复方向 |
|---|---|---|---|
| 1 | **重复/同质** | 任意两单元的价值/情绪/机制是否相同且无升级？ | 合并、替换一类、或改造其功能（作过渡/对比） |
| 2 | **割裂/清单** | 把单元随意换序，观感是否几乎不变？ | 加脊柱/连接物（同人物/同目标/同物件/同时间） |
| 3 | **松散/情节可删** | 删掉某单元，整体是否几乎无损失？ | 让它承担功能（埋设/回收/对比/转折），否则删 |
| 4 | **头重脚轻** | 最强高潮/奇观是否在开头或前段，结尾弱？ | 峰值后移；开场用"承诺"而非"一次放完" |
| 5 | **价值抵消/反差失序** | 相邻单元基调是否打架、互相削弱？ | 调序、加过渡、或改造 |
| 6 | **承诺-交付不符** | 开头承诺的体验，整体是否没兑现？ | 补兑现段，或降低承诺 |
| 7 | **拥挤/未发展** | 单元太多、每个都"过一遍"没深度？ | 删减到"少而深"，给每单元足够停留 |
| 8 | **伪发展** | 变化是否只在换地点/换道具，体验组织方式没变？ | 改发展轴（让"增长的东西"真的变） |

> **诊断纪律**：先判是否**阻断性**（会导致结构不成立）→ 再判实质性（可当前修）→ 一般性（记录）。不把轻微措辞问题当返工理由（对齐 README「问题处理区分轻重缓急」）。

## 8. 方案必要性删除测试（落实模块二移交的"M3 接口"）

> 模块二曾把 **M3「方案必要性：删除它，当前方案失去什么」降为模块三接口/待研究概念**。本手册将其落成可操作工具。

**与模块二"单项不可替代性"的区别（关键，防混淆）**：
- 模块二比的是**两个单项体验的价值能否互相替代**（脱离方案结构）。
- 模块三比的是**在给定方案结构中，某单元的功能是否可被删除/替换**（依赖方案结构）。

**三层判断**（对每个单元）：
| 层 | 问句 | 若"是" |
|---|---|---|
| ① 结构必要性 | 删掉它，脊柱/弧线是否断裂或接不上？ | 必要 |
| ② 铺垫/回收必要性 | 删掉它，是否有某条 setup 落空、或某条 payoff 失去依据？ | 必要 |
| ③ 反差/节奏必要性 | 删掉它，是否失去一处关键对比或造成节奏塌陷？ | 必要 |
| 若 ①②③ 皆"否" | 该单元在**本方案**中非必要 | 可删 / 可并入 / 可替换（**不否定其单项价值**） |

> **用途**：既防"删错重要过渡/铺垫"，也防"塞满漂亮但可删的场景"。是识别"松散"和"拥挤"的主力工具。

---

## 9. 多方案比较与交付

- 至少产出 **2–3 个方案**（同一批单元，不同脊柱/角色/顺序）。
- **比较维度**（定性，不评分不排名）：① 整体承诺匹配度；② 发展是否自然（有无真发展轴）；③ 组合层价值是否成立；④ 缺陷风险（§7 命中数）；⑤ 交付边界（哪些依赖模块五/导演）。
- **交付**：把"推荐候选方案 + 理由 + 未决项"交导演；**Agent 不选终稿**。

---

## 10. 质量与验收（何时可说"组合可靠"）

一次组合设计可称"**组合可靠（研究意义）**"需同时满足：
1. **整体承诺**能解释"为什么是这些单元、为什么这个顺序"；
2. 单元间有**明确关系**，且至少一种**增值关系**；
3. 有**一条清晰的发展轴**（真发展，非伪发展）；
4. 至少一条**埋设-回收**线贯穿；
5. 有**组合层价值**（§6 命中 ≥2 类），且删掉任一单元会影响整体（非拼盘）；
6. 无 §7 中**阻断性**缺陷（重复/割裂/头重脚轻/承诺不兑现等）。

> **"组合可靠"≠"观众一定会喜欢"**：真实观众效果、留存、迁移到 AI 第一人称短片的有效性**均未验证**（无后台数据、未做观众实验）。"可靠"仅指**结构与推理层面成立**。

---

## 11. 适用边界与已知局限（如实）

1. **无观众数据**：不虚构留存曲线或观众心理；"结构吸引力"是**分析判断**，非实测效果。
2. **迁移未验证**：本方法的霍格沃茨应用（见迁移案例）为**研究候选**，在 AI 第一人称短片上的有效性**尚未实证**。
3. **结构不能替代价值判断**：模块三不重判价值；遇到"值不值得"回模块二。
4. **结构不能替代注意力设计/可行性**：钩子与留存→模块四；技术预算→模块五。
5. **定性工具**：不评分、不排名、不设权重；允许"两方案都可"。
6. **样本偏差**：野兽先生结构规律以成功作品为主，幸存者偏差；F 旅程/探索型样本不足，HOGWARTS 须并用模块一的空间/陪伴研究（其本身亦未验证）。
7. **不越级**：本手册不给"最终创意"，不锁定任何场景，不代导演决策。
